# Hot Deal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [x]) syntax for tracking.

**Goal:** เพิ่ม Hot Deal ที่มีราคาของตัวเอง ตั้งเป็นช่วงวัน แสดงล่วงหน้ารายวัน และซ้อนทับราคาเดิมโดยคง visual status ของ Holiday/Promotion.

**Architecture:** daily_price เหลือ Holiday/Promotion. ตาราง hot_deals เก็บหนึ่งแถวต่อบ้านพักต่อวัน. Service ฝั่ง server สร้าง CalendarDayPrice จาก daily price, hot deal และวันปัจจุบันใน Asia/Bangkok; UI รับ display model แล้ว mutation ผ่าน endpoint Hot Deal แยก.

**Tech Stack:** Next.js 16.3.4 App Router, React 19, TypeScript strict, Supabase SSR, Zod 4, Vitest, Testing Library.

**Spec:** docs/superpowers/specs/2026-09-04-hot-deal-design.md

## Global Constraints

- อ่าน guide ที่เกี่ยวข้องใน node_modules/next/dist/docs/ ก่อนแก้ Route Handler หรือ component ที่พึ่ง Next.js.
- ใช้ TypeScript strict; ห้ามเพิ่ม any; server ใช้ client จาก lib/server.ts เท่านั้น.
- Date-only เป็น date และหา “วันนี้” ใน Asia/Bangkok.
- Hot Deal ทับราคาเท่านั้น: Holiday คงพื้นเหลือง, Promotion คง ✦, Hot Deal active เพิ่ม 🔥.
- Mutation validate input/property ฝั่ง server, ส่งเฉพาะ error code เดิม, require confirmation ก่อน overwrite/delete.
- ห้ามเพิ่ม anonymous RLS policy; ห้าม deploy จริงจนกว่า auth/RLS ตาม CONTEXT.md พร้อม.
- ทุก task ทำ TDD: test fail → run RED → implementation ต่ำสุด → run GREEN.

create table public.hot_deals (
  id uuid primary key default gen_random_uuid(),

  show_before_days integer not null check (show_before_days between 0 and 365),

export interface HotDeal {
